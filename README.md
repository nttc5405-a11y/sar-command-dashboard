# 特搜場控即時看板

**上線網址**：https://sar-command-dashboard.onrender.com/
**GitHub repo**：https://github.com/nttc5405-a11y/sar-command-dashboard

## 這是什麼、能做什麼

這是給消防特搜隊「場控組」在演習或任務時使用的即時看板網頁。放在固定電腦大螢幕
或指揮車上的裝置打開，可以：

- 自動顯示「目前時段」的整體狀況：階段、區域、傷患編號、INJECT、LEMA會議、
  OCC會議、拍照攝影、救護車司機、後送醫院。
- 顯示六個小組（總控A、總控B、現場A、現場B、傷控A、傷控B）目前時段的任務、
  負責人、位置。
- 如果目前時段是「休息」狀態，畫面會用明顯的顏色跟「休息中」標籤標示出來。
- 可以手動切換查看「其他時段」（事後回顧任一時段做了什麼），並提示「正在查看：
  X月X日 XX:00（非目前時段）」，一鍵可以「回到目前時段」。
- 多人（不同裝置）可以各自輸入「處置時序記錄」（時間、事件分類、狀態、備註），
  供事後檢討使用；記錄列表會自動每 15~20 秒更新一次，不用手動重新整理。

畫面資料有兩種來源：
- **示範模式（mock）**：讀取本資料夾內的 `mock-data.json`，全部是虛構的假資料，
  純粹用來看畫面長怎樣、按鈕邏輯對不對，不需要任何額外設定。
- **真實模式（live）**：透過 Google Apps Script 連到真正的「場控時序」Google Sheet，
  顯示真實演習資料，需要先完成下面「正式啟用前的一次性設定」。

## 如何在瀏覽器直接打開看示範模式

1. 直接用瀏覽器（建議 Chrome）打開這個資料夾裡的 `index.html`（滑鼠雙擊即可）。
2. 預設就是「示範模式」，會自動載入 `mock-data.json` 裡的假資料，可以馬上看到
   完整畫面效果（包含一段標示為休息的時段、幾筆示範處置記錄）。
3. 想確認設定面板長怎樣，可以點右上角「⚙ 設定」按鈕打開。
4. 在示範模式下，「新增處置記錄」表單送出後，記錄只會暫時出現在畫面上
   （存在瀏覽器記憶體），重新整理頁面後就會消失——因為示範模式沒有真正的
   後端可以寫入資料，這是已知、刻意的限制，不是bug。

## 正式啟用前，需要做的一次性設定（詳細步驟）

這些步驟只需要做一次（之後每次換新演習檔案，只要做「步驟 4」就好，不用重新部署）。
Claude 沒辦法幫你點 Google 的畫面、也不能幫你登入或按「允許授權」，這幾步請你自己
照著做，有任何畫面看不懂都可以截圖貼給我問。

### 步驟 1：建立「看板控制中心」Google Sheet

1. 瀏覽器打開 [sheets.new](https://sheets.new)，會自動建立一份新的空白試算表。
2. 把檔名（左上角「未命名的試算表」）改成：**看板控制中心**。
3. 把預設的分頁（左下角「工作表1」）改名成：**設定**（在分頁名稱上點兩下即可改名）。
4. 在「設定」分頁貼上以下內容（直接選取下面整塊文字複製，貼到 A1 儲存格，Google
   Sheets 會自動依 Tab / 換行分成正確的欄位跟列）：

   ```
   項目	值
   場控時序檔案網址或ID	（這欄先留空，等步驟3轉檔完成再回來填）
   演習開始日期	2026-10-15
   ```

5. 在畫面最下方點「＋」新增一個分頁，改名成：**處置記錄**。
6. 在「處置記錄」分頁的 A1 貼上這一列標題（一樣整段複製貼上）：

   ```
   ID	時間戳記	事件分類	狀態	內容備註
   ```

   下面不用填，之後看板新增記錄會自動一列一列加進來，你也可以自己手動補登。

### 步驟 2：Apps Script 一定要讀得到「當月場控時序檔案」——但它只能開 Google 原生試算表，不能直接開 .xlsx

這是唯一比較繞的地方：Apps Script 的 `SpreadsheetApp.openById()` 只能打開 Google
自己的試算表格式，不能直接打開 Excel 的 .xlsx 檔案，所以「10月場控時序.xlsx」要先
轉存一份 Google 試算表版本：

1. 到 Google 雲端硬碟，找到「10月場控時序.xlsx」這個檔案。
2. 在檔案上按右鍵 → **「使用以下應用程式開啟」→「Google 試算表」**。
3. 開啟後，選單列點 **「檔案」→「另存為 Google 試算表」**，這會產生一份**新的**、
   獨立的 Google 試算表檔案（原本的 .xlsx 不會被動到）。
4. 把這份新檔案的網址列複製起來（網址長得像
   `https://docs.google.com/spreadsheets/d/一長串英數字/edit`）。
5. 回到步驟 1 的「看板控制中心」試算表，把這個網址貼到「設定」分頁 B2
   （「場控時序檔案網址或ID」那一列的值）。

**以後每次演習換新檔案，只要重做這個步驟 2（轉檔＋把新網址貼進設定分頁），
不用重新部署 Apps Script。**（這幾個點擊動作之後也可以請 Claude 用瀏覽器幫你點——
但前提是你要先在 Claude 的瀏覽器分頁裡自己登入 Google 帳號，Claude 不能也不會
幫你輸入帳號密碼登入；沒有先登入的話，Claude 沒辦法用工具直接把整份檔案內容
搬過去轉檔，實測那個做法行不通。）

### 步驟 3：部署 Apps Script

1. 回到「看板控制中心」試算表，選單列點 **「擴充功能」→「Apps Script」**，
   會開一個新分頁，裡面預設有一個空的 `Code.gs`。
2. 把預設內容全部刪掉，改貼上這個專案資料夾裡 `apps-script/Code.gs`
   （[apps-script/Code.gs](apps-script/Code.gs)）的**完整內容**。
3. 按左上角儲存（磁片圖示，或 Ctrl+S）。
4. 右上角點藍色的 **「部署」→「新增部署作業」**。
5. 類型選齒輪圖示旁的 **「網頁應用程式」**。
6. 「執行身分」選 **「我」**；「具有存取權的使用者」選 **「所有人」**（因為場控組
   會用不同裝置存取，沒有登入機制）。
7. 點 **「部署」**。這時候 Google 會跳出「授權必要」的畫面，請你自己選擇自己的
   帳號、按「允許」（這一步一定要你本人親自按，Claude 不會也不能代你按）。
8. 授權完成後，畫面會顯示一組網址，格式類似：
   `https://script.google.com/macros/s/AKfycb.../exec`，把它複製起來。

### 步驟 4：驗證 Apps Script 真的讀得到資料（很重要，不要跳過）

1. 把上面複製的網址貼到瀏覽器網址列，後面加上 `?action=timeline`，整個貼上去
   開啟，例如：`https://script.google.com/macros/s/AKfycb.../exec?action=timeline`
2. 應該會看到一大串 JSON 文字（不是錯誤訊息、不是空白），內容包含
   `"columns"`、`"rows"`、`"groups"` 這些欄位，而且裡面的值看起來是「10月場控
   時序」實際的資料（不是全部空白）。
3. 如果看到的是錯誤訊息（例如「找不到分頁」），把錯誤訊息截圖給我，我可以
   幫你對照 `Code.gs` 的邏輯抓問題。

### 步驟 5：把 Apps Script 網址接上看板

1. 打開看板網頁（`index.html`），點右上角「⚙ 設定」。
2. 把步驟 3 拿到的網址貼到「Apps Script 網址」欄位，按「儲存網址」。
3. 把下面的選項切換成「使用真實資料」。
4. 這時畫面應該會顯示真正的場控時序資料。如果卡在「載入中」或跳出錯誤，
   回頭檢查步驟 4 有沒有真的驗證通過。

### 步驟 6：部署到 Render + GitHub（已完成）

- GitHub repo：https://github.com/nttc5405-a11y/sar-command-dashboard（Public）
- Render Static Site：https://sar-command-dashboard.onrender.com/
- 之後要更新網頁內容，只要把改好的檔案 `git push` 到 GitHub 的 `main` 分支，
  Render 會自動重新部署，不用手動操作。

## 新功能：演習結束後一鍵匯出「花費時間統計」報表

這個功能讓場控組演習結束後不用再手工做 Excel 統計表，直接在看板上點一下
「📊 產出花費時間統計報表」按鈕，就會自動產生一份格式跟過去手工範本一致的
Google 試算表（日期／演練階段／地點區域／作業項目／開始時間／結束時間／
花費時間(分鐘)／備註／總計），同一演練階段＋地點區域連續的任務會自動合併
儲存格並加總分鐘數。

**如果你是在「既有」已經部署過的看板控制中心 Sheet 上更新這次的程式碼**
（不是重新從頭建立一份），除了照步驟 3 把新版 `Code.gs` 貼進 Apps Script 編輯器，
還要多做這兩件事，這次更新才會真的生效：

1. **手動補標題**：打開「看板控制中心」試算表的「處置記錄」分頁，在 F1、G1、H1、I1
   四個儲存格分別補上「記錄類型」「作業名稱」「演練階段」「地點/區域」這四個標題文字
   （程式不會自動幫你補標題列，只會從第 2 列開始正常寫新資料，已存在的舊資料列不受影響）。
2. **重新部署新版本**：光是在 Apps Script 編輯器按「儲存」（磁片圖示）**不會**讓正式的
   exec 網址吃到新程式碼！一定要回到「部署 > 管理部署作業 > 點編輯（鉛筆圖示）
   > 版本選『新版本』> 部署」，新程式碼才會真的生效。部署用的 exec 網址不會改變，
   看板前端設定面板裡原本貼的網址不用重新貼。

**「新增處置記錄」表單多了哪些欄位、怎麼用：**

- **記錄類型**：預設是「單點事件」（跟以前一樣，維持原本的用法）。如果這筆記錄是某個
  「有開始、有結束」的具體任務（例如「實木切割」從幾點開始、幾點結束），記錄類型改選
  「開始」或「結束」，並且填上一致的**作業名稱**（例如都叫「實木切割」）——系統會自動
  用同一個作業名稱把「開始」跟「結束」兩筆記錄配對起來，算出花費了幾分鐘，寫進報表。
- **演練階段**、**地點/區域**：下拉選單的選項是從目前看板時段資料裡自動抓出來的
  （不用自己打字），選單最後都有「其他（自行輸入）」，選了會跳出文字框讓你自己打。
- 這四個新欄位只有「產出花費時間統計報表」用得到；如果只是像以前一樣記單點事件，
  記錄類型維持預設的「單點事件」、不用理會作業名稱/演練階段/地點區域也完全沒問題。

## 檔案說明

| 檔案 | 用途 |
|---|---|
| `index.html` | 看板主頁面 |
| `style.css` | 畫面樣式（支援手機直向到大螢幕投影的響應式排版）|
| `app.js` | 前端邏輯：抓資料、畫畫面、處理互動 |
| `mock-data.json` | 示範模式用的虛構測試資料 |
| `apps-script/Code.gs` | 要貼到 Google Apps Script 編輯器的後端程式碼 |

## 重要提醒（隱私）

`10月場控時序.xlsx` 與 `場控時序_結構分析.md` 這兩個檔案含有真實隊員姓名等資料，
已經在 `.gitignore` 裡排除，不會被上傳到 GitHub。請不要把這兩個檔案的內容複製貼到
本資料夾其他檔案裡。
